1. Why a subset

Seven rounds of fixes to txc_filter_files() were each measured by a ten-hour rebuild of the November feeds, and the PDF and LSOA reports moved only modestly per round. The national kept-file listing diff found every regression; the reports did not. So the loop was changed: pick the routes where the sources disagree, pull every TransXChange file of the operators behind them (the filter compares files within an operator and line, so a whole operator keeps its decisions unchanged), and run filter, conversion and counting on that subset in under an hour per build.

5. What the files showed, and the rules

Each disagreeing route was traced to the files each source kept (scripts/route_subset_audit/show_files.py, scratchpad diag/trace2.R). Round 8 changed txc_filter_files() in fifteen steps (8a-8o), each with a fixture test that fails on the build before it; everything else the traces found is data, not filter. Steps 8f-8o were found by the national kept-file listing, the subset rerun or the full rebuild after a change: 8f repairs two regressions of 8a and 8c, 8h one of 8f, 8i two of 8c and 8e, 8j one of 8b and one of round 7, 8k-8l extend 8j, 8m repairs one of 8b, and 8n and 8o are older faults the same check turned up.

Round 8a - a file is on one side of a school calendar only if all of it is. The filter records, per file, which side of a ServicedOrganisation calendar it runs on, so that a term-time and a holiday version of one timetable are both kept. It took the side from any journey. First Norfolk & Suffolk publishes each edition of a route as the whole timetable plus a few calendar-bound extras: route 64’s edition from 25 October had four holiday-only extras, its successor from 1 November some term-only ones. The two looked like opposite sides, neither replaced the other, and every Ipswich journey of routes 63, 64 and 65 ran twice (BODS TXC 52 departures at the reference stop against 31 in the timetable). Calendar tokens are now recorded only when every journey is bound to the calendar (txc_all_journeys_bound()).

Round 8b - files sharing an operator and ServiceCode are compared as one registration. Files were grouped by operator, normalised description and line set, and a pair sharing few journeys was treated as siblings. Four routes in the subset ran twice because of that:

Route What separated the two files Effect
London United 117, 411 (BODS) description retyped; December 2025 edition fully retimed (3% shared) 2023 timetable ran beside the 2025 one
Dartline PR1, PR1A (BODS) Dartline’s files have no description; the second export does every journey twice
Kempsford K2 (BODS) revision 3 retimes revision 2 from the same start date (0% shared) both revisions ran
First Berkshire 7 (BODS) line set 7, 7X against 7 18 October edition ran beside 1 November’s

Files sharing operator and ServiceCode are now grouped as well, provided they publish a line in common (Arriva Cymru’s code “12/X12” covers two routes). Within such a group a pair that fails the shared-journeys test is still treated as versions when the files come from different exports (modification time more than an hour apart, or a different revision) and the smaller has at least half the journeys of the larger. The export test keeps siblings written together apart (Stirling UL, 41 ms); the size test keeps supplements apart (Hodgsons 87, 26 journeys and 6; Red Eagle W20, 15 and 2). The stale-version rule gained the same shared-line test. The identical-period tie-break now compares revision numbers as numbers.

Round 8c - the parts of a split registration are not editions of each other. West Midlands Bus publishes ServiceCode PD2093720:4 as two files per edition, “WA” (lines 8 and 9, 147 journeys) and “WN” (line 9, 250), written minutes apart but with their own revision numbers. The 8b export test read different revisions as different exports, so the 15 November WA was taken for a retimed edition of the 1 November WN and both WA files - the Inner Circle - were dropped. The export test now prefers the modification time (more than an hour apart) and falls back on the revision only without one; and a file with a sibling in its own export is compared as a retimed edition only with a file publishing the same lines.

Round 8d - one creation time does not make two files siblings, and excluded dates tell week variants apart. Equal creation times with different ServiceCodes were read as siblings of one export. But TNDS keeps the registration’s creation time through every edition: Stagecoach Midlands’ route 85 is three open-ended editions (WM_SC_SCNH_85_1, _4_A, _3_A, all created 8 December 2021, modified September, October and November 2026), every journey shared, and all three ran - 63 departures at Coventry against 21 in BODS. Equal creation times now mean siblings only within one export or where the journeys differ. Separately, Metrobus files route 23 as one weekday file running only the week of 19 October, one running every other week, and a school-extras file, sharing code, line, period, weekdays and nearly every journey; they differ only in the service’s DaysOfNonOperation date ranges. The filter now reads those ranges and a file running on under half the other’s dates is a variant beside it, not a version of it (txc_dates_shared()). That restored fourteen Metrobus routes that BODS TransXChange had at 0.

Round 8e - a much smaller file is not a successor. Hodgsons’ 87N is the six evening journeys of route 87 from 20 November 2024, beside the 26-journey weekday file from two days before that carries the same evening times. The versions test passed on the small file’s journeys and closing the weekday file deleted its 20 daytime journeys. A file with under half the journeys of the one before does not replace it - as for the retimed and stale rules - and the stale rule now also needs its successor from another export (Hodgsons writes the Saturday and evening files in one).

Round 8f - two regressions the national listing found. (1) 8a’s all-journeys test removed the calendar side from morebus U3’s term and holiday files (Bournemouth University, from 2 November 2026): the holiday file carries 112 Christmas journeys on MondayToSunday excluded from every date but one, the term file three that run only a few weeks. Neither was “wholly bound”, so both lost their side and the identical-period tie-break deleted the holiday file (174 journeys). A journey excluded from at least half the file’s period now counts as bound - dated extras, not a whole timetable. First 64’s plain journeys carry no such ranges, so 8a still holds. (2) 8c’s switch to modification times made Yorkshire Coastliner’s 31X - Easingwold-Kirkbymoorside (14 October 2025) and Easingwold-York (15 October), one ServiceCode, one stop of 88 in common - look like an edition and its retiming, and Kirkbymoorside was deleted. A retimed edition must now run over the same stops (half their union, the measure the handover and stale rules use).

Round 8g - editions renamed and recoded are still compared. Stagecoach Merseyside’s route 33 is NW_SC_SCMY_33_2 (“Maghull Station - Maghull Station”, August 2026) and NW_SC_SCMY_33_1 (“Maghull - Maghull”, October), both open-ended with every journey the same. Neither description nor ServiceCode matched, so the two were never compared and both ran (48 departures against BODS’s 24; 31 and 31A likewise). Files sharing operator, creation time and line set now form a group too; 8d’s rule then separates siblings of one export from editions across exports.

Round 8h - the stops a route calls at, not the stops a file lists. 8f compared the StopPoints each file declares. Hodgsons’ 2024 BODS exports declare every stop the operator served: 160 for route 79, which calls at 50, and 28 for route 60, which calls at 8. Against the 2026 editions (43 and 21 declared) the overlap fell below half, the old exports stopped being editions, and the subset rerun showed route 79 back at 20 departures for TNDS’s 9 (60 and 60A doubled likewise). The test now uses the stops the journey patterns call at, where the editions agree (40 of 53 for route 79, 8 of 8 for 60 and 60A); 31X’s two files still share 1 of 88. The same change keeps EYMS’s Castle Howard - Malton file for route 81 open past 19 December: 8e took the York - Castle Howard edition starting 20 December, 3 shared stops of 92, for its successor and would have ended the Malton section with it.

Round 8i - a later, newer file is the next edition, however short. The BODS listing showed First’s weekly editions running side by side over Christmas. First Somerset files route 4 as one registration in weekly editions: 13 December (41 journeys, revision 858), Christmas week (20, revision 859) and New Year (33, revision 860, five minutes after Christmas). Two guards stopped them chaining: 8e’s small-successor rule (Christmas has under half the journeys of the week before, so it was taken for a supplement like Hodgsons’ 87N) and 8c’s one-hour export window (Christmas and New Year were taken for parts of one export). A file that starts later and is also the newer, by modification time or else by revision, is now from a later export, and the small-successor guard applies only within one export, which is where 87N sits (revision 45, one modification time). The same guard had stopped West Midlands Bus’s X21/X22 term/weekend split from 8e on (term file 217 journeys to 528), and BODS ran both files in full: 221 X21 trips on the check day against 112 (TNDS 109). It also lets Hodgsons’ current three-file export of school route 879 close the 2021 upload it replaces (BODS 6 departures at the reference stop, the same double count as BODS GTFS, down to 3; TNDS 2).

Round 8j - two faults the control routes showed. Of the 2,042 routes where the sources agreed under round 6b, the ones that stopped agreeing were checked file by file. (1) West Midlands Bus files school route 705/788 as two parts of one export with one period, “WA” (five journeys, lines 705 and 788) and “WB” (two, 705); WB’s 07:54 passed the versions test against WA’s 07:55 and the identical-period tie-break deleted WA and line 788 with it (BODS 4 departures for 1, and 2 for 0, from round 8b). A repeated upload carries the whole timetable, so within one export a file under half the size of the other no longer replaces it. (2) National Express West Midlands’ route 96 ran beside West Midlands Bus’s from 1 November (BODS 99 departures at Chelmsley for 66). NX published an open-ended file from 30 August and a last edition for 25-31 October; rules 2 and 3 set the ended edition aside, as they must for trentbarton’s half-term weeks, and West Midlands Bus retimed the route at the takeover (61 of 100 departure times kept), so the handover rule’s versions test failed. A kept file now records the end of any later, newer edition of its registration that has ended, and the handover rule accepts that end, the day before the new operator starts, in place of the timetable match; the stop and day tests still apply. The other control changes are corrections: First Berkshire 7X is not in First’s timetable from 2 November and its registration’s November edition drops it (BODS 0; TNDS’s 45 is a per-line file nothing supersedes, and BODS GTFS repeats it), and Gateshead’s PR1 weekday file, wrongly dropped in round 8b, is back (94, as BODS GTFS).

Rounds 8k and 8l - the rest of the 1 November takeover. The 8j change sat inside the handover rule, which pairs files with exactly the same lines, so it closed route 96 and nothing else. West Midlands Bus took over National Express’s Birmingham and Coventry routes on 1 November with different line sets: NX’s 11A/11C became West Midlands Bus’s 11A/11S and 11C, NX’s 66 became 66/66A, Coventry’s 20/20A/20B became 20/20A, and 22 became 22/22A. The announced handover is now a separate pass: a kept file whose registration has an ended last edition, and which is still running after that end, is closed there if files from another operator start the next day, share a line with it, and between them cover at least half its stops and all its days. 8l adds that each of those successor files must itself run largely over the old route (half the stops of the smaller file): First Worcestershire’s 20/20A/20B also starts on 1 November and shares the line numbers, but runs in Worcester. In the national listing for the November 2026 BODS archive the pass closes five more NX files on 31 October - 11A/11C (weekday and weekend), 66, Coventry 20/20A/20B and 22, 3,883 journeys between them - and changes nothing in TNDS.

Round 8m - two depots’ documents for one route. The national before-and-after check of the full rebuild (8i against 6b) moved one PDF route the wrong way: First Essex 3, Chelmsford - Southend, BODS TXC from 0.85 of the timetable to 0.40. Both of First Essex’s Chelmsford and Hadleigh depots work the route and each publishes its own document for the whole of it under the one registration (PF0000599:376): interleaved times, the same stops, separate creation dates (7 and 29 September 2021) and separate revision series (697-726 and 413-420), both re-issued for December, Christmas and New Year. The retimed-edition test of round 8 (same registration, another export, comparable size, same stops) took each depot’s file for an edition of the other’s, and the identical-period tie-break dropped Chelmsford’s. A document that a new one replaces is not edited again once the new one appears; a depot’s document is kept up beside the other. Files whose documents each have at least two editions in the registration, written over overlapping spans, are no longer retimed editions of each other.

Round 8n - line names in any case. The same national check (every file the November 2026 BODS listing dropped between round 7c and round 8l, 191 files) found the First Essex depot files and nothing else wrong. All the other drops were checked: First’s 25 October editions and NX’s half-term weeks, superseded as intended; old Hodgsons, Hawkes 891, John Dix 2025 and PC Coaches 49 editions replaced by current ones; Blueworks’ X70F, whose one journey is in X70; Kempsford’s 768, whose July file and September file carry the same weekday times. It also showed Kempsford’s K2 still keeping two of its three editions: the July file names the line “k2” and the later two “K2”, so they shared no line and were never compared (38 journeys a day for 19). Line names are now compared in upper case.

Round 8o - a takeover copy dated before the takeover. The files the same listing newly kept since round 7c were checked too. Most are National Express editions that rule 2’s round-7 fix restored and that now end on 31 October or 14 November, as they should. But for routes 9, 11/11A, 52 and others West Midlands Bus published copies of NX’s timetables on 21 October dated from NX’s own start, 30 August, with the same journeys (448, 374, 342). The handover rule skips two files that start on the same day, and the announced-handover pass of 8k wanted a successor starting the day after NX’s last edition ended, so both operators’ copies ran from 30 August to 14 November. The pass now also accepts another operator’s file dated earlier if it carries the outgoing timetable (the versions test, and at least half of the outgoing file’s journeys in it), and starts that file at the takeover. Another operator already running its own journeys on the route - a joint service - fails the journey test and is left alone.

Measurement fixes. The reference-stop lookup is now case-insensitive (BODS writes Hodgsons’ 13004000A as 13004000a, which showed as 0 departures). First’s timetables mark school-day and school-holiday columns with SD/SH codes on a line below the service numbers; the reader (first_reader.py) now reads those and counts a school day, which brought the six First routes from “unreliable” to exact agreement with both feeds.

Not filter faults.

  • Welsh independents. TNDS Wales carries Phil Anslow, Harris Coaches, Adventure Travel and Thomas of Rhondda; BODS carries none of their files. Their routes 1, 6, C16, C18, X1 and 173 share numbers and streets with Stagecoach’s, and the seed’s stop-overlap match joined them. TNDS was not double-counting. The seed now refuses a stop-overlap match between two operators the NOC register identifies as different.
  • Per-day-type files. Red Eagle W20 and Select 8 publish a weekday and a Saturday file of one timetable; both are rightly kept. Their gaps between TNDS and BODS are in the data.
  • Preston Bus 35 and 8. Each source keeps the right files; BODS publishes three day-type files, TNDS one. The difference is in the journeys.

6. How the DfT builds BODS GTFS (bods-integrated-data, commit b35a847f, 30 Oct 2026)

Read from the source (src/functions/txc-processor, gtfs-timetables-generator, tnds-txc-retriever, bods-txc-retriever, shared/schema/dates.schema.ts).

Inputs. The BODS bulk archive and the BODS coach archive, every file; every TNDS zip except NCSD (coach now comes from BODS). A TNDS service is processed only if its zip is L, S or W (London, Scotland, Wales) or its mode is coach, ferry, metro, tram or underground. English TNDS bus is never read.

No file versioning. Every service in every file is loaded unless its EndDate is before today; there is no StartDate test, so future-dated files load too, and nothing chooses between versions of the same registration. The only deduplication is at the end, in SQL: DISTINCT ON (route_id, service_id, ticket_machine_journey_code, direction, origin_stop_ref, destination_stop_ref, departure_time) ORDER BY revision_number DESC. Two versions of a timetable with different calendars have different service_ids and both survive; two files whose Line ids differ get two routes and both survive. That is the 3.7% of duplicate runs measured earlier, and the 2-3x counts for National Express West Midlands and First Berkshire 7 in section 4.

TNDS against BODS. The route key is NOC + LineName. A TNDS service whose NOC + LineName already exists from a BODS file is skipped as a duplicate - only if the BODS file was processed first, and only on that exact key. Where London files carry a different NOC in TNDS and BODS both load, which is the London doubling.

Calendars. Start = max(StartDate, today), end = min(EndDate, start + 9 months): the feed never says what ran before the build date. A journey with no operating profile at any level runs Monday to Sunday. Serviced organisation working days are read from every matching organisation, holidays only from the first (.find).

Bank holidays. AllHolidaysExceptChristmas includes St Andrew’s Day (fixed 30 November) and AllBankHolidays includes that group, for every service in Great Britain. So any English or Welsh service that declares <DaysOfNonOperation><AllBankHolidays/> is cancelled on 30 November - the ~37,000-trip St Andrew’s Day drop, mostly London.

Modes. Mode is mapped to route_type as written (bus 3, coach 200, ferry 4, metro/underground 1, rail 2, tram 0; anything else bus). Nothing corrects a file that files a heritage railway as tram or the DLR as rail.

For us. BODS GTFS England bus is BODS TransXChange with no version selection: an upper bound, not a reference. Its London, Scotland and Wales bus is TNDS, so a TNDS vs BODS GTFS agreement there says nothing about the data. The DfT “merge” is not a comparison of services: it is BODS first, TNDS only where BODS has no route on the same NOC + line, and only for L/S/W and non-bus modes.
